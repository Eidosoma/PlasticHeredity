# CR7 administrative extension-readback amendment

Status: specified after the original CR7 process stopped and before result
assembly resumed. This amendment changes no scientific definition,
simulation, seed, cohort, controller, action, outcome, inference draw,
confidence interval, gate, or conditional-extension rule.

## Trigger

The checksum-registered CR7 runner completed all 96 primary state batches,
all 96 primary replay batches, all 96 conditional active-extension batches,
and all 96 extension replay batches. The conditional extension could only
have started after the original primary and integrity gates passed. The
runner then stopped while constructing the extension reporting table, before
creating the final result directory.

No checkpoint is missing. No scientific lineage will be regenerated by this
amendment.

## Root cause

Primary checkpoints bind directly to the natural launch-state digest. An
extension checkpoint deliberately has a stronger identity: its digest binds
both the natural launch state and its exact parent primary checkpoint:

```python
sha256(original_case_digest + primary_batch_digest)
```

That stronger extension identity is correct and is checked when each
extension checkpoint is loaded. The generic table-construction helper,
however, contains a primary-only assertion requiring every supplied batch to
carry only `original_case_digest`. It therefore rejects a correctly loaded
extension batch before reading any outcome value.

## Fixed operation

The amendment leaves every persisted checkpoint untouched. After the real
extension checkpoint has passed its registered parent-bound identity check
and after generated-versus-replay digests have matched exactly, a temporary
reporting view replaces only its `case_digest` field with the original case
digest expected by the generic table helper. The lineage tuple, final states,
actions, outcomes, record digests, RNG states, and all numerical arrays remain
the identical objects:

```python
reporting_batch = replace(
    extension_batch,
    case_digest=original_case_digest,
)
```

The reporting view is not written back to a scientific checkpoint and is not
used for replay verification. It exists only to satisfy the generic helper's
primary-batch precondition after the stronger extension identity has already
been verified.

The registered runner was launched with Python's `-m` mode, so its checkpoint
dataclasses were serialized under the runtime name `__main__`. The additive
reader maps those two names back to the byte-identical registered
`SteeringBatch` and `LineageSummary` classes before unpickling. This is a
serialization-name compatibility alias only; it does not transform checkpoint
content.

## Validation and resumption

Before resumption, the amendment must:

1. verify the original CR7 registration, validation, and smoke checksums;
2. verify the original registered source tree is unchanged;
3. verify all four sets of 96 checkpoints are present and readable;
4. verify every primary checkpoint against its original case digest;
5. verify every extension checkpoint against its original case plus exact
   parent-primary digest;
6. verify primary and extension generated/replay digests are exact;
7. reproduce the generic helper's metadata rejection without reading effect
   sizes;
8. prove on an artificial metadata fixture that the reporting view changes
   only `case_digest` and leaves the lineage tuple object-identical;
9. pass the full repository test suite; and
10. seal amendment source hashes and stopped-run provenance before assembling
    any scientific result.

Resumption recomputes inference deterministically from the already completed
checkpoints, applies the original gates, creates the original registered
reports, runs exact artifact readback, and adds explicit amendment provenance.

## Claim boundary

This amendment can repair final reporting only. It cannot change whether CR7
passed, cause the extension to run, alter an effect estimate, weaken a check,
or authorize CR8 or CR9.
